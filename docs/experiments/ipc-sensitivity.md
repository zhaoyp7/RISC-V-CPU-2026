# IPC 延迟与窗口容量敏感性（2026-10-25）

> 本文件为前置仿真阶段记录；后续三组diagnose与当前判断见[窗口PPA实验](ipc-window-ppa.md)。

## 结论

外部响应延迟和有效窗口容量都有明显影响。保持RTL不变，LATENCY=10→5 时 W2 IPC
0.538263→0.640466（+18.988%）；10→1 时为0.751973（+39.704%）。
默认10拍延迟下，ROB32+PRF64为0.607639（+12.889%）；完整窗口组合为0.639400（+18.790%）。
单独PRF64逐例周期完全相同，单独IQ16/LSQ32仅+0.160%/+0.016%，不能按独立扫描结论否定组合收益。

下一步优先对 **ROB32/PRF64/IQ8/LSQ16** 做一次独立diagnose，先确认最小有效扩容的面积与频率代价；
IQ16/LSQ32作为有实测依据的后续组合，避免直接叠加所有容量。原配置默认值不改。
本轮完成仿真测量，没有新RTL或综合，也没有将任何容量组提升为PPA候选或合入main。

## 测量对象与控制

功能检查点1d142db / ipc-uncontended-wake-20261025；所有24个生产输入与该检查点diagnose报告逐字节一致。
W2/CDB2、LSU在途队列8项、双bank I$各1KB及分支预测参数固定。
ROB32组配PRF64；另外单独测PRF64，ROB效应应与这个控制组比较，不把配套PRF扩容混为ROB效应。
每个宏都有ifndef保护，覆盖参数只注入独立Verilator wrapper；由生成的C++成员宽度复核每组实际生效的
ROB、PRF、IQ和LSQ容量。没有修改cpu_config.sv、Makefile、config.mk、scripts/、官方filelist或SRAM。

官方make perf MAX_CYCLES=50000000、固定相同程序/答案；总计26个配置×延迟点、312次逐例perf调用。
每点普通/LOCAL_STATS输入hash、stdout答案、周期逐项相同，ROB提交数等于软件指令数；
检查IQ/LSU/ROB排他分类、LSQ查询分类、load所有权互斥和SAFE_WAKE真实获准。
七个新容量组各自qsort→hanoi→queens顺序通过，再各自W2 correctness 19/19；无工具错误或重试。
无新增IMPLICIT/UNDRIVEN/LATCH；原有IQ packed树UNOPTFLAT提示仍在。
此处只验证W2容量扫描，不声称这些参数已经过W1或完整run_all验证；功能RTL本身沿用既有两档完整回归。

## 外部延迟扫描

| LATENCY | 原配置W2 IPC | 较10拍变化 |
| --- | ---: | ---: |
| 1 | 0.751973 | +39.704% |
| 3 | 0.690726 | +28.325% |
| 5 | 0.640466 | +18.988% |
| 10 | 0.538263 | +0.000% |
| 20 | 0.408695 | -24.071% |

LATENCY控制官方RAM读/写响应到期时间，指令和数据共用该设置，保留所有内部流水及AXI排队。
所以这是整体外部响应敏感性，不能当成D-cache实测收益，也不是任何具体缓存设计的严格上界。
qsort/rsort队首load在已发内存请求后的等待占比，10拍为38.87%/43.83%，1拍为14.76%/19.41%。
计数器跨模块有重叠，百分比不可相加，也不可直接作为可节省周期。

## 容量与延迟交叉对照

| 容量覆盖（其余保持默认） | 1拍IPC | 10拍IPC | 10拍相对收益 | 20拍IPC |
| --- | ---: | ---: | ---: | ---: |
| 原配置 ROB16/PRF48/IQ8/LSQ16 | 0.751973 | 0.538263 | +0.000% | 0.408695 |
| 仅 PRF64 | 0.751973 | 0.538263 | +0.000% | 0.408695 |
| ROB32 + PRF64 | 0.799565 | 0.607639 | +12.889% | 0.462333 |
| 仅 IQ16 | 0.754169 | 0.539124 | +0.160% | 0.409173 |
| 仅 LSQ32 | 0.752024 | 0.538350 | +0.016% | 0.409689 |
| ROB32 + PRF64 + IQ16 | 0.824229 | 0.618536 | +14.913% | 0.468888 |
| ROB32 + PRF64 + LSQ32 | 0.799999 | 0.620532 | +15.284% | 0.481017 |
| ROB32 + PRF64 + IQ16 + LSQ32 | 0.823935 | 0.639400 | +18.790% | 0.494159 |

以ROB32+PRF64为固定基础，补齐IQ8/16×LSQ16/32的四种组合，避免把所有组合收益归到ROB。
IQ16在原配置只+0.160%，在ROB32基础上+1.793%；LSQ32在原配置只+0.016%，
在ROB32+IQ16基础上+3.373%。ROB32+LSQ32、IQ8为0.620532（+15.284%），
再扩IQ16达到0.639400（额外+3.041%）。这些增益不能线性相加。
高延迟下扩窗口仍不能消除等待：完整组合20拍IPC0.494159，低于原配置10拍的0.538263。

完整组合去掉收益最大的vvadd，其余五项几何平均仍提升11.842%；总体提升并非只有一个样例贡献。
ROB32后rsort的IQ满阻塞从20.18%升至64.54%，扩IQ16后为46.58%；这是阶段间压力转移，
不是“阻塞占比上升所以整体变慢”。qsort/rsort在完整组合中仍有35.16%/41.30%的队首load内存等待。

## 验收与后续筛选

容量组只有IPC实测，不能沿用原配置400 MHz diagnose或main的456.12 MHz opt，也不能宣称整体加速18.79%。
最小ROB32+PRF64组的IPC提升12.889%；以同模式400 MHz原配置比较，IPC×Fmax打平约354.33 MHz，
相当于频率最多下降11.417%才打平。该值只用于筛选，面积约束和最终opt仍需单独测量。
先对最小组获取一次diagnose；若代价过大，优先研究ROB/PRF结构和有效窗口利用，
若代价可接受，再逐项比较LSQ32和IQ16，保留有净收益的组合。不要继续只依据wake机会次数选择下一轮RTL。
对内存路径继续研究时，应再区分取指、load和store响应贡献；本次整体LATENCY实验未完成这种归因。
